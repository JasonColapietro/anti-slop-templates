Overview

The Suede Registry is a permissionless authorship ledger. When a creator registers a work, three things happen atomically: a cryptographic fingerprint of the file is recorded, an ERC-8004 author identity is bound to that fingerprint, and a machine-readable license record is attached. The resulting entry is permanent, inspectable, and agent-readable.

The registry does not store the work itself — only its fingerprint and provenance metadata. Storage is the creator's concern. Proof is the registry's.

Note

This document describes the v1.0 protocol. All field names and on-chain structures are stable. The agent API is in release candidate status; minor additions are expected before general availability.

Identity model

Every author on the Suede Registry holds an ERC-8004 identity — a sovereign, chain-agnostic claim of authorship that travels with the work across networks and marketplaces. The identity is not a username; it is a cryptographic binding between a public key, a human-readable author handle, and the works attributed to that key.

Author identity vs. wallet address

A wallet address is a payment destination. An author identity is a reputational record. The two are linked during registration but are deliberately separate: you can rotate your payment key without invalidating your authorship record, and you can present your author identity without disclosing your wallet.

Identity records are indexed by the registry's resolver and exposed over a standard REST and GraphQL interface — the same surface that autonomous agents query when evaluating a work for licensing.

Spec

ERC-8004 defines IDENTITY, REPUTATION, and VALIDATION roles. The Suede Registry implements all three. Third-party resolvers implementing only IDENTITY are considered partially conformant.

Record structure

Each registry entry is serialized as a JSON document before being hashed and committed on-chain. The canonical shape is defined below.

Field reference

Field Type Description
schema string Protocol version identifier. Always suede/registry/v1 for this revision.
id string (ULID) Globally unique record identifier, sortable by creation time.
work.sha256 hex string SHA-256 digest of the original file bytes. This is the canonical fingerprint.
author.identity DID string The author's ERC-8004 decentralized identifier. Resolvable via the Suede resolver.
timestamp ISO 8601 UTC time at which the registration transaction was included in a block.
chain.block integer Block number of the registration transaction. Verifiable against the chain explorer.
license.spdx SPDX ID Machine-readable license expression. Agents parse this field for use-rights evaluation.
license.royalty_bps integer Royalty rate in basis points (100 bps = 1%). Enforced on-chain for commercial uses.

Hashing pipeline

Before any record is committed, the file passes through a deterministic normalization pipeline. This ensures that two independently computed hashes of the same work — regardless of container format or metadata tags — produce an identical fingerprint.

  1. Strip mutable metadata. Audio ID3 tags, EXIF fields, and document author properties are extracted and stored separately. They do not contribute to the hash.
  2. Normalize byte order. For formats with endian-variant encoding (e.g. WAV chunks), the normalizer rewrites to little-endian before hashing.
  3. SHA-256 over raw content bytes. The hash is computed over the normalized payload, not the file wrapper.
  4. Encode as hex. 64-character lowercase hex string, stored verbatim in the record.

Caution

Transcoding a lossy file (e.g. MP3 → WAV → MP3) will produce a different hash than the original, even if the audio content sounds identical. Always register the source master — not a derivative export.

License terms

License terms are attached at registration and encoded directly in the on-chain record. They are immutable once set; a creator wishing to change terms must register a superseding record and link it to the original via the supersedes field.

The registry accepts any SPDX expression as the license.spdx value. For compound terms — such as non-commercial for individual use, commercial with royalties for enterprise — use the SPDX WITH operator. The Suede resolver exposes a rights.evaluate(context) method that agents call to get a binary decision for a given use context.

Agent API

Autonomous agents — trading bots, content pipelines, AI training orchestrators — interact with the registry through a structured JSON-over-HTTP API. No wallet connection is required to query records; write operations require a signed ERC-8004 message.

Resolving a work by fingerprint

Given a SHA-256 hash of a file, the resolver returns the matching registry record, including the license terms and the author's identity DID. Agents use this to determine whether use is permitted before processing the asset.

CLI reference

The Suede CLI provides a one-command interface for creators registering works from the terminal. It handles normalization, signing, and submission without exposing private keys to the network.

Note

The CLI never uploads your file. It computes the fingerprint locally and submits only the hash, metadata, and your signature. The signing key stays on your machine or in your connected hardware wallet.
