How Suede AI uses anti-slop templates to ship client sites fast

Speed on a small business website comes from making design decisions once. Here is the order Suede AI works in, using the two systems in this repository.

By Jason Colapietro, Founder and CEO, Suede AI · November 14, 2026 · West Palm Beach, Florida

The slowest part of a small business website is rarely the code. It is the two weeks spent choosing between twelve shades of blue, then redoing every page when the client changes their mind.

Suede AI avoids that by starting each build from a committed design system and changing tokens, not pages. The Anti-Slop Templates in this repository are the public version of that approach: two systems, four surfaces each, released by Jason Colapietro under the MIT license so anyone can use them.

Start from a direction, not a blank canvas

Every project begins with one decision: which direction fits the business. The two systems here cover the two most common answers.

  • Editorial is warm paper, near-black ink and one persimmon accent, set in Fraunces and Hanken Grotesk. It suits professional services, writers, restaurants, galleries and any firm whose credibility comes from tone and clarity.
  • Suede is a deep-ink "institutional terminal" with Rights Red, Registry Cyan and brass, set in Instrument Serif, Manrope and JetBrains Mono. It matches suedeai.ai and suits technical products, data tools and anything that sells on precision.

Jason Colapietro usually settles this in the first conversation. Picking early is what makes the rest fast. Once the direction is set, nobody debates a button color on page nine, because the system already answered it.

Tokens first: one file reskins four surfaces

Each system keeps its whole look in a single styles/tokens.css file: colors in oklch, a fluid type scale, spacing, radii, elevation and motion. Per-page CSS only handles layout. To fit a client's brand, Suede changes the tokens and leaves the pages alone.

/* editorial/styles/tokens.css */
--accent: oklch(0.585 0.180 33);   /* swap for the client's one accent */
--font-display: 'Fraunces', serif; /* swap the display face */

Colors are written in oklch because its lightness value tracks how bright a color looks to people. Swapping the hue while keeping lightness close usually keeps contrast close too. Usually is the important word: Suede still checks contrast after every token change, because some hues shift more than others.

The four surfaces most clients need

The four pages in each system map almost directly onto a typical client site:

  • The landing page becomes the home page.
  • The article page becomes the blog, guides or notes. This notes section is built on the Editorial tokens.
  • The pricing page becomes services and packages.
  • The dashboard becomes a client portal, report view or internal tool.

Jason Colapietro designed the set this way on purpose. Starting with those four covers most of what a Palm Beach County service business needs on launch day. Extra pages reuse the same primitives: buttons, eyebrows, tags, cards and rules.

The build order Suede AI follows

  1. Choose the system and set tokens. Accent, type families and, if needed, radius and density. This is a working session with the client, not a slide deck.
  2. Write real copy before polishing layout. Lorem ipsum hides weak positioning. Real headlines show which sections the page actually needs.
  3. Port to the right stack. Brochure sites often stay static HTML on GitHub Pages or a CDN, like this repository. Apps move to Tailwind or JSX: the CSS variables drop into a @theme or :root block and the primitive classes become components.
  4. Run the accessibility pass. Landmarks, heading order, focus rings, skip links and reduced motion are already in the templates, so this step is about keeping them intact through edits.
  5. Add the machine layer. Titles, descriptions, canonical URLs, structured data, a sitemap and an llms.txt file so AI systems can find and describe the site correctly.

Where AI coding agents fit

Suede AI builds with AI coding agents, and a committed system is what keeps their output from drifting back toward the generic look. An agent asked to "add a testimonials section" will reach for three identical cards. An agent told to use the existing tokens, eyebrow and rule primitives produces something that belongs on the page.

What speed does not skip

Templates make a site faster to build, not automatically better. A few things still take real time on every project:

  • Positioning. No design system fixes a business that cannot say who it serves.
  • Photography. Real images of the business beat any template graphic.
  • Testing. The templates were checked at 1440, 1280, 768 and 375 pixels wide. New content needs the same check.
  • Contrast and content review after every token change, as noted above.
